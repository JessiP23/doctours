| 22  | Level 1 | Booking states are exactly `confirmed`, `cancelled`, `superseded`, with `replaced_by` linking a rebooking to what it replaced.                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | A rebooking is not a cancellation: the trip moved, and an operator must be able to read what happened. `superseded` plus the link keeps that history, while the Level 0 partial unique index — only one _confirmed_ booking per kind — lets the replacement sit beside the row it replaced with no schema change. | 23  | Level 1 | Cancellation cancels the **hotel first**, requires `confirmed: true` plus a reason in the tool schema, and reports a partial failure by naming the booking that is still live.                                                                                                                                                                                                                                                                                                                                                                                                                           | The hotel carries a deposit and a free-cancellation deadline, so it is the leg where delay costs money; the flight is unticketed and voidable at this stage. | 24  | Level 1 | A disruption is detected by **re-reading the order and comparing Sabre's per-segment status and times against what was booked**, and recorded in a `trip_events` table that the agent must raise before answering anything else.                                                                                                                                                                                                                                                                                                                                                                         | There is no cancellation feed in CERT, and there is no honest way to pretend otherwise. | 25  | Level 1 | **The order is the truth about a booked trip, not the shop.** Create Booking reads the order back and stores the times Sabre holds, which is what the agent quotes and what disruption checks compare against; Flight Shop's cached schedule is treated as a quote, not a record. No tolerance window softens the comparison — the baseline is authoritative, so any difference is a real change. | 26  | Level 1 | **No map, no rendered widgets for the patient — the conversation stays the whole interface.** Two patients asked for a small map after booking. | 27  | Level 1 | **The traveller count is established, never assumed**, and it lives on the conversation's trip rules with a flag saying whether the patient confirmed it. One to four people; every traveller needs their own passport details and goes on the room; a room filed as sleeping fewer is not offered. Changing the count after a booking exists is refused, because that is a rebooking rather than a setting — the honest path is cancel and rebook, and the tool says so.                                                                                                                                |
| 28  | Level 1 | **A rebooking sells before it releases.** The replacement flight or room is bought first and the old order cancelled only once the new one exists — the reverse order can leave a patient holding nothing, and a failed sell has to be a no-op. Two live orders is a state an operator can fix; a comfortable lie about it is not, so a failed release is reported by reference and never described as cancelled.                                                                                                                                                                                        |
| 29  | Level 1 | **Rebooking reuses the passports already on file**, stored on the booking row at sale time. A patient whose flight the airline cancelled is not asked for their date of birth again. | 30  | Level 1 | **No passport number is collected.** The ticket is issued on the name, date of birth and gender the patient gives, which is what Create Booking files. Nothing here files travel documents (SSR DOCS), so asking for a passport number, expiry or nationality would mean holding sensitive data for no purpose. The agent says instead that the airline will need the passport at check-in and that the name and date of birth must match it. A production build would file DOCS and then — and only then — would collecting it be right.                                                                |

| 33  | Level 1 | **The agent speaks first when something happens to the trip.** The brief puts proactive notification under Level 3, but a cancellation the patient learns about only after typing — or at the airport — is not handled, it is filed.
